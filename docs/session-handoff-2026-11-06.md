# 농가 입점 신청 조회·수정 구현 기록

저장일: 2026-11-06 (한국 시간)

## 사용자 요청과 결과

열매담 운영자가 공급처 입점 관리의 농가 이름을 클릭하면 신청 내용을 보고 수정할 수 있도록 구현했다. 기존 승인·수수료 저장과 입점 취소는 그대로 사용할 수 있다.

- 농가 이름을 밑줄·연필 아이콘이 있는 버튼으로 변경했다. 클릭하면 입점 신청 내용·수정 창이 열린다.
- 업체명, 로그인 이메일, 신청일, 승인 상태를 확인한다. 업체 유형(농가/직매장/유통업체/기타), 대표자, 연락처, 주소, 사업자등록번호, 주요 취급 과일, 소개를 입력·수정한다. 로그인 이메일은 조회 전용이며 인증 계정을 변경하지 않는다.
- 기존 가입에는 이름과 이메일만 저장되어 있었으므로 미작성 항목은 빈칸과 안내로 표시한다. 원래 없던 신청 내용을 임의 생성하지 않는다.
- 새 공급처 가입 양식에도 같은 추가 항목을 제공한다. 기존 계정 생성 흐름을 유지하도록 추가 항목은 선택 입력으로 제공하며, 입력한 경우 형식과 길이를 검증한다.
- 수정은 운영자만 가능하다. 업체명을 바꾸면 상품의 공급처 표시 이름도 함께 갱신한다. 기존 승인 여부·수수료율·계정 이메일·권한·이용권·주문·정산은 변경하지 않는다.
- 변경 성공 후 목록을 갱신하고 수정 창을 닫는다. 실패하면 창과 입력값을 유지하고 오류를 표시한다. 배경 클릭·Esc로 닫히지 않으며 X로 닫는다. 모바일은 한 열로 배치하고 창 내부에서 스크롤한다.

## 저장과 접근

- Member의 선택 필드 supplierApplication에 신청 정보를 저장한다. 새 가입에서는 기존 Supabase Auth 가입 요청의 metadata에 검증한 신청 정보를 함께 넣고, 첫 인증 로그인에서 commerce 프로필에 복사한다.
- 운영자가 먼저 수정한 가입 대기 프로필의 신청 정보는 후속 계정 연결 시 덮어쓰지 않는다.
- updateSupplierApplication 액션은 서버에서 현재 운영자 권한과 대상 공급처를 확인하고 허용한 필드만 수정한다. 다른 공급처와 일반 셀러는 접근할 수 없다.
- 신청 정보는 기존 회원 snapshot의 관리자 목록과 본인 계정 정보에만 포함된다. 공개 공급상품 응답에는 신청 연락처·주소·소개를 추가하지 않는다.
- 별도 외부 업체·AI API 연결은 추가하지 않았다. 실제 운영 농가의 데이터를 테스트로 수정하거나 가입 메일을 발송하지 않았다.

## 상품 상세 창에서 운영자 수정 연결

- 사용자 스크린샷의 대상은 입점 신청서가 아니라 농가가 등록한 공급상품 상세 창이었다. 기존 운영자 상품 관리 목록의 수정 기능에 더해, 상품 상세 창에도 운영자용 ‘상품 정보 수정’ 버튼을 추가했다.
- 운영자로 로그인한 상태에서 실제 등록 상품을 열면 기존 공급상품 수정 양식으로 이동한다. 상품명·특징·원산지·품종·사진·과세·보관·배송·옵션·공급가·수량을 기존 값으로 채운다. 일반 셀러와 체험 예시 상품에는 이 수정 버튼을 표시하지 않는다.
- 기존 supplierProduct 저장 API와 권한 검증을 그대로 사용한다. 저장 시 기존처럼 검수 대기가 되며 운영자 상품 관리에서 승인한다. 상품 소유 공급처와 등록 ID는 기존 값으로 전달한다. 별도의 자동 승인이나 외부 API 호출을 추가하지 않았다.
- 검증: 프로덕션 빌드·타입 검사 통과. 브라우저 임시 응답으로 운영자 상품 상세→수정 양식→특징 수정→저장을 확인했고 상품 ID·공급처·사진 2장·옵션 공급가 19,000원·수량 99가 유지됨을 검사했다. 일반 셀러 상세에서는 수정 버튼이 없음을 확인했다. 실제 운영 상품 변경·AI·이메일·결제 호출 없음. 확인용 탭과 로컬 서버 종료.

## 운영자 수정 후 상품 카드가 사라지는 문제 수정

- 사진 파일 삭제가 아니라 저장 로직이 모든 수정을 검수 대기로 돌려 공개 목록에서 숨기던 문제였다. 운영 DB에서 감홍사과 상품의 상태가 pending이고 대표 사진·갤러리 3장 모두 남아 있음을 확인했으며, 비공개 저장소의 세 사진을 Sharp로 읽어 정상 크기를 확인했다.
- 운영자가 같은 공급처의 기존 상품을 수정하면 이전 판매 상태(판매 중/검수 대기/중단)를 유지한다. 따라서 판매 중 상품은 계속 공개 목록에 남고 중단 상품이나 검수 대기 상품을 자동 공개하지 않는다. 신규 등록, 농가 직접 수정, 공급처 변경, 판매 중 상품의 사진 전체 삭제는 검수가 필요하다. 클라이언트에서 보낸 status는 사용하지 않는다.
- 운영자 기존 상품 수정 버튼은 ‘상품 수정 저장’으로 바꾸고 안내·성공 메시지도 저장으로 구분했다. 신규 상품과 공급처의 수정은 기존 검수 요청 버튼을 사용한다. 이 결정은 위 기록의 일률적인 검수 대기 저장 설명보다 우선한다.
- 검증: 프로덕션 빌드·타입 검사, 실제 Auth 임시 계정 통합 검사 통과. 운영자 승인 상품 수정 후 공개 목록 포함, 사진·공급처 보존, 사진 필드 생략 편집, 중단/대기 상태 유지, 농가 수정 재검수, 공급처 변경·사진 삭제 시 재검수를 검사했다. 브라우저 격리 응답으로 변경된 저장 버튼과 수정 후 상품 카드·사진 유지·성공 안내를 확인했다. 실제 AI·메일·결제 호출 없음. 임시 테스트 데이터와 확인용 서버·탭 정리.
