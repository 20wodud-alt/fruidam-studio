## 서비스의 방향

과일을 판매하려는 셀러가 공급상품을 선택하고 상세페이지를 만들어 자신의 외부 판매 채널에서 판매한다. 소비자 주문은 열매담에 직접 입력하거나 엑셀로 등록한다. 농가·직매장은 운영자 승인과 상품 검수 후 공급하고 소비자에게 직접 배송한다. 열매담은 상세페이지 제작, 상품 공급 연결, 발주·배송·문제 접수·정산 관리를 제공한다.

셀러는 이메일 가입 후 즉시 체험한다. 공급처는 입점 승인이 필요하다. 운영자는 공급처 승인, 상품 검수, 공급 수수료 관리, 분쟁 중재와 정산 확인을 맡는다. 첫 출시는 국내 판매·국내 배송이다.

## 확정 요금과 권한

| 요금제 | 가격 | 제작 건수 |
| --- | --- | --- |
| 무료 체험 | 0원 | 가입 후 3일간 상품 1개 미리보기 |
| 건별 결제 | 9,900원 | 1건 |
| 기본 구독 | 월 39,000원 | 5건 |
| 성수기 플랜 | 월 79,000원 | 10건 |
| 단체 플랜 | 월 199,000원부터 | 25건부터, 관리자 포함 총 5명 |

- 무료 체험도 AI 이미지 생성 3회. 실제 비용 확인 후 조정한다.
- 완성본 첫 다운로드 때 1건 차감. 같은 완성본 재다운로드 무료. 다른 상품·디자인의 새 완성본은 추가 1건.
- 월 제공 건수는 이월하지 않는다. 추가 제작은 건당 9,900원.
- 구독 중 전체 공급상품 발주 가능. 건별 구매 상품과 유료 제작을 완료한 상품은 구독 없이도 계속 발주 가능.
- 구독은 월 자동 갱신, 해지하면 다음 결제부터 중단하며 결제한 기간까지 사용한다는 기획이다.
- 팀은 관리자 1명과 구성원 4명. 제작 건수 공유, 구성원은 자기 주문·배송지·문의만 열람, 관리자는 팀 전체 열람이라는 기획이다.

## 확정 상품·주문·정산 정책

- 공급처가 실제 사진과 원산지·품종·중량·크기·등급·구성·공급금액·출고 정보를 등록하고 운영자가 검수한다.
- 같은 상품의 중량·등급 옵션은 상세페이지 하나에 포함하며 옵션별 재고·공급가를 관리한다.
- 실제 상품 사진을 포함하고 AI는 배경·연출에 추가 사용한다. AI 연출은 표시하고 사실 정보는 등록값을 유지한다.
- 공급처 자료를 셀러의 판매 채널에 사용할 수 있도록 동의받는다.
- 세로형 전체 이미지·구간별 이미지·상품명·판매 문구를 제공한다.
- 셀러 결제금액과 수수료 산정 기준은 모두 배송비 포함 총 공급금액이다. 실제 약정 수수료율은 공급처별 설정한다.
- 결제 승인 후 발주 확정 및 재고 차감이 목표다. 공급처별로 발주를 분리하며 첫 버전 합배송 할인은 없다.
- 결제 완료 → 출고 준비 → 배송 중 → 배송 완료. 출고 준비 전 취소, 이후 공급처 확인이라는 기획이다.
- 공급가·구성·배송 조건 변경은 관련 셀러에게 알리며 기존 결제 주문 금액은 유지한다.
- 소비자 문의는 셀러가 받고, 상품·배송 문제는 사진과 함께 주문에 접수해 공급처가 처리한다. 운영자는 분쟁을 중재한다.
- 배송 완료·취소 환불 제외·분쟁 없는 주문을 주 1회 정산한다. 실제 송금은 운영자가 직접 하고 지급 완료를 기록한다.
- 사이트 내 알림·이메일, 주요 알림은 카카오 알림톡 우선·실패 시 문자로 대체하는 기획이다.

- 브라우저 격리 응답으로 실제 상품 상세 버튼→입력 첫 단계, 상품명·옵션·사진 3장 자동 입력, 이름·대표 사진 수정→디자인 기획안→구성안 편집 전환·저장 프로젝트 URL 확인. 예기치 않은 AI 생성 경로를 차단한 상태에서 테스트했고 호출 없음. 운영 상품·계정 변경 및 이메일·AI·결제 호출 없음. 로컬 서버 종료.

## 연동 특징 입력란의 부가 정보 제거 (2026-11-03)

- 사용자 요청에 따라 ‘이 상품으로 상세페이지 만들기’로 가져오는 ‘상품의 특별한 점’에는 공급상품의 등록 특징 문구만 그대로 채운다. 자동 덧붙이던 원산지·공급처·품종·연도·보관·출고·배송·추가 운임 문구를 제거했다.
- 상품명·사진·옵션 자동 입력과 원본 공급상품 정보는 유지한다. 이미 저장된 편집 작업을 일괄 수정하지 않고 새로 가져오는 흐름에 적용한다.
- 검증: 프로덕션 빌드·TypeScript·diff 검사와 실제 Auth 임시 계정 통합 검사 통과. 가져오기 API와 기본 source 프로젝트의 features가 등록된 원문과 정확히 같은지 검사했다. 사진·옵션, 권한·체험·수정 입력 저장 등 기존 검사도 통과했고 임시 데이터 정리 완료. 실제 이메일·AI·결제 호출 없음. 로컬 서버 종료.

## 과일 구성안 카피·이미지 연출 개선

- 공급상품 생성 경로에도 기존 Gemini 카피 작성을 연결했다. 등록 특징 원문은 입력 자료로 보존하고, 구성안에서는 후킹·핵심 포인트·특징별 설명·먹는 장면을 새 문구로 작성한다. 외부 검색을 추가하지 않고 기존 Gemini에 상품 문구만 전달한다.
- 대표·옵션은 원본 사진을 유지한다. 새 공급상품의 사진 방향은 원본+AI 혼합이며, 산지·과육 접사·탑뷰 식탁의 서로 다른 섹션을 골라 최대 3회 생성한다. 이미지 생성에는 기존과 같이 참고 원본 사진 최대 2장을 보낸다. 생성 이력·연출 표시·시도 한도·자동 재시도 없음은 유지한다.
- 기존 작업은 구성안 상단 ‘과일 구성 다듬기’로 적용한다. 현재 초안을 먼저 저장하고 문구·이미지 방향을 다듬은 뒤 비어 있는 연출 슬롯을 생성한다. 작업 중 편집했으면 응답 적용을 멈추며 문구 적용과 이미지 변경은 기존 실행 취소 이력에 남긴다. 기존 저장 작업 전체를 일괄 변경하지 않는다.
- Gemini 미연결 시 기본 과일 카피를 적용하고 연결 필요를 안내한다. 실제 생성 성공으로 표시하지 않는다. API 실패 시 기존 작업은 유지한다.
- 검증: 프로덕션 빌드·타입 검사, fruit-composition 모의 Gemini 검사, 실제 Auth 임시 계정 통합 검사(타인 구성 접근 차단 포함), 브라우저 모의 응답으로 구성 버튼 1회·이미지 3회·저장·실행 취소 확인. 실제 AI·이메일·결제 호출 없음.
- 통합 검사 서버: `$env:FRUIDAM_AI_FIXTURE='1'` 설정 후 `node -r ./tests/mock-gemini.cjs ./node_modules/next/dist/bin/next start --hostname 127.0.0.1 --port 3010`, 별도 터미널에서 `node tests/commerce-integration.mjs`. 모의 서버 표식이 없으면 검사를 시작하지 않는다. 운영 배포에는 이 설정을 추가하지 않는다.

- 기존 구성안 문구를 다시 작성하기 전에는 계정 접근을 확인한 저장 원본을 별도 JSON으로 백업한다. 로컬은 `data/backups/{projectId}`, 운영은 비공개 자산 버킷 `backups/{projectId}`를 사용하며 사진 목록이나 공개 API로 노출하지 않는다. 백업 실패 시 기존 구성안을 변경하지 않는다.
