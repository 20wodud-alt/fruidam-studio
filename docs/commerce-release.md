# 판매 서비스 1차 배포

최근 운영 배포와 브랜드 변경까지 포함한 현재 상태는 [STATUS.md](STATUS.md)를 참고한다.

## 실제 연결된 기능

- `/`: 열매담 서비스 홈. `/catalog`: 공급상품 검색·분류·상품 상세. `/pricing`: 확정 요금제.
- `/login`: Supabase Auth 이메일 가입·인증·로그인. HttpOnly 쿠키 세션, 만료 시 refresh.
- `/seller`: 개인별 제작 내역, 이용권, 주문·배송, 문제 접수, 사이트 내 알림.
- `/supplier`: 입점 승인 대기, 승인 후 상품·옵션·공급가·재고·실제 사진 등록, 검수 요청, 송장 등록, 정산 내역.
- `/admin`: 공급처 승인·배송비 포함 수수료율 설정, 상품 검수·승인·중단, 정산 지급 기록.
- 운영자 상품 관리에서 직접 상품을 등록·수정하거나 승인된 공급처를 선택해 대리 등록할 수 있다. 빈 목록에도 첫 상품 등록 버튼을 제공한다. 직접 관리 상품도 검수 대기로 저장하고 승인 후 공개한다.
- 등록 양식은 기본 정보·사진·보관·배송·옵션으로 구분한다. 최대 10장 사진/대표 선택, 상품 태그·품종·과세 여부·생산연도·보관 정보·출고형태·택배사·지역 추가 운임과 옵션별 등급·중량·규격·과수를 저장한다. 상품 상세의 갤러리/정보표/옵션 목록과 사진 ZIP 다운로드, 상세페이지 제작 자료에 연결한다. 지역 추가 운임은 직접·엑셀 발주에서 배송지역을 선택해 건당 1회 합산한다.
- `/studio`: 기존 상세페이지 편집기 유지. 상품 상세의 제작 버튼은 상품 정보 입력 단계로 이동해 상품명·설명·옵션·원산지 등 정보와 등록 사진을 채운다. 확인·수정 후 구성안 만들기에서 개인 작업을 생성하며 원본 공급상품은 유지한다. 관리자와 승인된 공급처도 등록 상품으로 제작 가능하며 계정별 작업 분리와 셀러 체험 제한을 유지한다.
- 무료 체험은 가입 후 3일 이내 1개 생성, 다운로드는 유료 제작 건수 필요. 제작 건당 AI 이미지 요청 최대 3회. 기존 운영자의 작업에는 새 제한을 소급하지 않음.
- 발주 직접 입력 및 상품별 엑셀 양식 다운로드·업로드(최대 200건/2MB). 유효하지 않은 행이 있으면 전체 등록 중단.
- 주문 등록은 결제 대기이며 재고를 차감하거나 실제 출고를 시작하지 않음. 서버가 공급가·권한·수량 검증.
- 원래 상세페이지 프로젝트·섹션·이미지는 보존. 별도 FRUIDAM_commerce 문서 테이블과 revision 검사 RPC 사용. RLS, anon/authenticated 직접 접근 차단.

## 운영자 첫 로그인

Vercel 배포 계정의 확인된 이메일을 서버 환경변수 `FRUIDAM_OWNER_EMAIL`로 지정했다. 해당 이메일로 가입하고 이메일 인증 후 로그인하면 운영자 역할이 부여된다. 가입 폼이나 사용자 metadata의 admin 값으로는 운영자 권한을 얻을 수 없다. 다른 운영자 권한은 서버에서 명시적으로 추가해야 한다.

기존 All Deployments Vercel Authentication은 유지한다. 이번 배포를 고객 대상 공개 서비스 개통으로 간주하지 않는다. 외부 고객 공개 전에는 기존 운영자용 studio/API의 비회원 접근까지 별도로 폐쇄하고 회원 기반 접근으로 전환해야 한다.

## 아직 연결하지 않은 운영 기능

사용자는 결제사·문자·알림톡 운영 계정이 없으며 화면·주문 기능을 먼저 배포하는 방향을 선택했다.

- 실결제, 건별 이용권 지급, 월 자동결제·해지·환불, 결제 승인 후 재고 차감은 미연결. 결제 완료나 이용권 지급을 흉내 내지 않음.
- 실제 정산 송금은 운영자가 별도로 수행. 시스템은 지급 기록만 관리.
- 이메일 업무 알림·카카오 알림톡·문자 발송은 미연결. Supabase의 가입 인증 이메일과는 별도.
- 단체 5명 초대·제작 건수 공유, 요금제 변경 세부 정책, 자동 재배송·환불 완료 처리는 후속 범위.
- 실제 공급상품은 입점·사진 등록·검수 후 공개. 홈의 과일 실사 사진 3종은 명시된 체험용 예시이며 실제 발주 불가. 사진 출처는 photo-credits.md 참고.

## 검증

`npm run build`, `npx tsc --noEmit`, 기존 Supabase·asset-store 검사. `node tests/commerce-integration.mjs`는 로컬 서버를 대상으로 임시 Auth 계정·태그된 데이터를 생성해 역할·상품 검수·개인 작업·체험 제한·발주 금액·일괄 등록 원자성·배송·알림·정산 기록을 검사하고 자체 데이터만 정리한다. 이메일 발송·AI 호출·결제는 수행하지 않는다.

데스크톱 및 모바일 브라우저에서 홈·상품 목록·요금제·로그인·공급처 진입과 기본 상호작용을 확인한다.
